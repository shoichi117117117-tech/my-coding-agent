\# Multi-Agent システム開発・UI/ロガー改修 引き継ぎドキュメント



\## 1. プロジェクトの概要と目的

本プロジェクトは、Obsidian および `LiteLLM` / `Google GenAI SDK` を活用したマルチエージェント形式の自動コーディングシステムです。

複数の専門エージェント（Planner, Coder, Tester 等）が協調してタスクを遂行し、開発者がターミナル上で進捗をリアルタイムかつ視覚的に把握できるインタラクティブな開発環境を構築しています。obsidianを用いて必要な知識を保存して各エージェントが必要なときにsearch_obsidian_vault()を用いて情報を収集します。


\---



\## 2. フォルダ構成と各ファイルの役割



```text

my-coding-agent/

├── agents/                  # 各エージェントの定義・ロジック

│   ├── base.py              # 全エージェントの基底クラス (BaseAgent)

│   ├── planner.py           # 計画・タスク分解を担当するエージェント

│   ├── coder.py             # コード記述・修正を担当するエージェント

│   └── tester.py            # テスト実行・検証を担当するエージェント

│

├── utils/                   # 共通ユーティリティ・UI・ロッガー

│   ├── ui.py                # AgentLogger (Richを使ったターミナル描画・スピナー制御)

│   └── logger\_config.py     # ファイルログ (logs/\*.log) やサードパーティログの抑制設定               

│

├── tools/

│   ├── code\_editor.py       # ファイル操作・コマンド実行等のツール群

│   ├── obsidian.py          # obsidianとの連携ツール群

│   └──  terminal.py          # terminalとのinteractするtool

│

├── tests/                   # 複数のfileをまたぐtestを実行

├── logs/                    # 実行ログの保存フォルダ (YYYY-MM-DD.log)

├── config.py                # APIキーやモデル優先度・フォールバック設定

└── main.py                  # システムのエントリーポイント



```



\---



\## 3. エージェントの連携フロー (ワークフロー)



1\. \*\*User Input (`main.py`)\*\*: ユーザーからの開発リクエストを受領。

2\. \*\*Planner Agent\*\*:

\* リクエストを分析し、具体的なステップやファイル構造の計画を作成。





3\. \*\*Coder Agent\*\*:

\* Planner の計画に基づき、`write\_file` などのツールを実行してコードを生成・修正。





4\. \*\*Tester Agent\*\*:

\* 変更されたコードの検証やテストツールを実行し、結果をフィードバック。





5\. \*\*BaseAgent (全エージェント共通の基盤)\*\*:

\* 設定されたモデルパイプライン（例: OpenRouter / Gemini / Groq）に従ってLLMを呼び出し。

\* 失敗時には自動でフォールバックモデルへリトライ。

\* 呼び出し状況やツール実行イベントを `AgentLogger`（`ui.py`）へ渡して画面描画。







\---



\## 4. これまでに対応・解決したこと



\### A. ターミナルの表示崩れ・不要な改行の修正



\* \*\*問題\*\*: LiteLLM の成功時コールバック（`\_custom\_litellm\_success\_callback`）が Rich のスピナー（くるくる）の停止制御を挟まずに `console.print` を割り込み実行していたため、巨大な空行が発生したりスピナーがフリーズする問題が発生。

\* \*\*対応\*\*:

\* `logger\_config.py` 内の重複していたコールバック処理を完全に削除。

\* LLMリクエストの表示処理を `BaseAgent.call\_llm` から `self.logger.log\_llm\_request` を呼ぶ形に一本化。

\* 描画とファイル保存の役割（UI表示は `ui.py`、ログ保存は `.log` ハンドラ）を綺麗に分離。







\### B. ツール実行ログの引数表示とパス文字列のモダン化



\* \*\*問題\*\*: ツール実行時（`Executing Tool`）の引数表記が固定化されていたり、Windows環境特有のバックスラッシュ（`\\`）や余計なエスケープ文字がそのまま出力されて不自然だった。

\* \*\*対応\*\*:

\* `AgentLogger.tool\_call` を拡張し、Dict（辞書）や JSON 文字列から引数のキー（`path`, `dir`, `query` など）を自動判定して適したラベルを表示するように変更。

\* パス中のバックスラッシュ（`\\`）をスラッシュ（`/`）に統一置換するクリーンアップ処理（`\_clean\_path\_slashes`）を追加し、ターミナル表示をモダン化。

\* 120文字を超える長い引数テキストの自動省略（`...`）に対応。

\* コード内のコメント・ドキュメントをすべて英語表記に統一。







\---



\## 5. 現在の状態と次のステップ



\* UI・ロガー周りのリファクタリング、バックスラッシュのクリーンアップ、エージェント連携ログの調整はすべて完了し、Git へコミット・Push 済みです。
